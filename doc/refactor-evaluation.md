# 重构与消融评测

## 设计取舍

用户在脑图中维护一份用例树，AI 按需求生成它或按节点 ID 提议修改。两种导出共享当前树。模型调用与业务结构校验留在服务端。对话使用 Vercel AI SDK 的消息、停止操作和流协议，工具状态用 shadcn/ui Trace 渲染。一次请求只上传当前树和最近 20 条文本消息，模型编辑取其中 12 条。 [AI SDK 对话](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot) · [shadcn/ui Trace](https://ui.shadcn.com/docs/components/base/trace)

体验上采用选中节点时预填上下文、显示可展开的真实执行过程、让人工与 AI 修改共享撤销重做。候选做法参考了 Agent 产品里的上下文动作和回退机制。 [Codex 上下文动作](https://developers.openai.com/blog/codex-as-a-platform) · [Cursor Agent](https://prod.cursor.com/help/ai-features/agent) · [Claude Code Checkpointing](https://code.claude.com/docs/en/checkpointing)

脑图底座对比了 SimpleMindMap 和 Mind Elixir。Mind Elixir 6.0.3 有原生编辑、快捷键、标签和增量刷新，合成的 50 条用例浏览器样例验证了普通文字安全渲染、标签保留和增量更新时保留节点元素。当前版本保留已完成端到端验收的 SimpleMindMap 适配。编辑器以外的用例结构、聊天和导出均使用项目自己的数据约定。 [Mind Elixir](https://docs.mind-elixir.com/) · [SimpleMindMap 的增量更新](https://wanglin2.github.io/mind-map-docs/en/api/constructor/constructor-methods.html#updatedata-data)

## 实验设计

- 旧版从 `ea6b411` 提取实现和锁文件。12 份合成需求与规则在运行前固定于 `eval/requirements.json`，其中 4 份复跑。两份资料从合成快照提供，缺失资料场景使用同一段可用正文。
- 各组通过同一本地网关使用同一模型。新版候选使用相同采样设置，每次只改变规划、并发或资料。旧版保留原调用方式，含显式 temperature 和结构化工具输出，作为端到端基线。
- 先按冻结的模式计数，再检查发布候选所有模式未命中的用例。本文区分模式计数与逐案复核。耗时是本机网关实测，存在同时运行的实验请求，数字只代表本次样本和环境。模型报告了表中各组全部请求的 Token，未换算价格。

| 路线 | 完成轮数 | 模式覆盖 | 首条可执行用例中位数 | 完成 P50 / P90 | 请求数 | Token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧版分模块 | 16 | 79/79 | 75.41 秒 | 492.31 / 530.51 秒 | 116 | 496,974 |
| 单次生成 | 16 | 67/79 | 31.72 秒 | 31.72 / 40.50 秒 | 16 | 30,231 |
| 规划后串行 | 16 | 75/79 | 29.85 秒 | 80.22 / 112.22 秒 | 72 | 120,669 |
| 规划后并发 2 | 16 | 72/79 | 28.67 秒 | 51.94 / 65.57 秒 | 70 | 117,152 |
| 去掉外部资料 | 3 | 0/17 | 无产物 | 6.26 / 7.03 秒 | 3 | 1,360 |

发布路线的 12 个模式未命中点均复核为同义或分步表达，逐案复核达到 **79/79**。下表给出可定位的依据。

| 样本 | 复核的覆盖点 | 用例里的依据 |
| --- | --- | --- |
| 邀请 | 单次接受 | 已完成的邀请不能再次被接受。 |
| 会议室 | 非工作日（两轮） | 无法成功预订非工作日的时段。 |
| 会议室复跑 | 并发和取消释放 | 恰好一名用户成功。取消后另一用户成功预订原时段。 |
| 退款 | 申请时限 | 超过 7 天的申请不被接受。 |
| 采购审批 | 禁止自审、修改再提交 | 无法批准或驳回自己的采购单。驳回后直接提交失败，修改后才进入待审批。 |
| 配额 | UTC 重置 | UTC 零点开始获得新的每日提交配额，本地日期切换时维持原配额。 |
| 密码重置 | 旧密码失效 | 原密码无法登录，新密码可以登录。 |
| 储物柜复跑 | 开门后失效 | 正确开门后，原取件码不能再次开启。 |
| 报告导出 | 访客受阻 | 访客无法成功导出报告。 |

- **默认一次生成。** 规划串行首条结果只提前约 6%，完成 P90 增加约 177%，Token 约为单次的 4 倍。并发 2 在分阶段路线中缩短了约 35% 的完成中位数，但模式覆盖由 75/79 降至 72/79，且分阶段路线整体未过门槛。保留兼容接口与可回放的分模块流程。
- **资料使显式规则可覆盖。** 有资料的 3 轮单次生成覆盖 16/17 个模式点，逐案复核为 17/17。去掉资料后 3 轮都无可交付用例。产品端在只有不可读链接时直接提示粘贴正文。
- **结构校验拦住已构造的无效输出。** 发布路线 16 轮真实结果通过结构校验，预置的空步骤、数量不匹配、编号错误和占位结果均被拦截。两份信息未定样本的预设无依据断言扫描均为零命中。
- **局部操作保留。** 改名、改优先级、删除、新增、修改步骤、澄清共 6 条真实对照。旧版和局部操作都为 6/6，未指定用例的变更数均为零。自动化另外验证了原子应用、无效操作回退和浏览器等待期间的手工编辑保护。

## 复现

用本地 `.env.local` 配好模型。结果逐样本写入 Git 忽略的 `.eval-results/`。为不同模型或配置另开干净工作区，避免混用已缓存结果。

~~~bash
for variant in baseline single serial parallel without-source; do
  TEST_CASES_LOOPBACK=1 node --env-file=.env.local --import tsx eval/run.mts "$variant"
done
TEST_CASES_LOOPBACK=1 node --env-file=.env.local --import tsx eval/edit.mts
pnpm --silent eval:cases report
~~~

可以在变体名之后加样本 ID，仅执行选定样本。原始响应和个人模型配置留在本地。
